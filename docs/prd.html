📋 Project Overview

The Expense Tracker is a full-stack web application designed to help a single user manage their personal finances by tracking expenses, setting budgets, and visualizing spending patterns through interactive charts and reports.

⚠️ Important Note: This is a single-user application without authentication or multi-user support.

Project Goals

  • Enable user to track daily expenses across multiple categories
  • Provide visual insights into spending patterns
  • Help user set and monitor budgets
  • Offer a clean, intuitive user interface
  • Implement CRUD operations for expense management
  • Learn full-stack development with React, Node.js, Express, and MySQL

Target Users

  • Students learning full-stack development
  • Individual users tracking personal expenses
  • Anyone looking for a simple, local expense management solution
Development Approach: Agile Scrum methodology with 6-hour sprints per week. Each sprint delivers incremental value with working features.

✨ Features & Requirements

Core Features

1. Dashboard

  • Welcome message with user's name (hardcoded: "Hello, Munaf Hajir")
  • Display total budget, total expenses, and remaining budget
  • Quick action buttons (Add Budget, Add Expense)
  • Category filter buttons (All Expense, Food & Drink, Groceries, Travel, Health)
  • Visual expense breakdown (pie chart)
  • Spending trend chart (bar chart)

2. Expense Management

  • Add Expense: Name, date, category, amount
  • Edit Expense: Modify existing expense details
  • Delete Expense: Remove expenses with confirmation modal
  • View Expenses: List view in table format
  • Categories: Travel, Groceries, Food & Drink, Health, Meal, etc.
  • Filter by Category: Click category buttons to filter expenses

3. Budget Management

  • Set total budget amount
  • Update budget amount
  • Automatically calculate remaining budget
  • Display budget metrics in real-time

4. Expense Analytics

  • Pie chart showing expense distribution by category
  • Bar chart showing spending trends
  • Category-wise expense breakdown
  • Color-coded categories for easy identification

5. Expense Tracker Table

  • Table with columns: Sr., Expense, Amount, Edit/Delete
  • Serial number auto-generated
  • Edit button (pen icon) for each expense
  • Delete button (trash icon) for each expense
  • Responsive design for mobile devices

Non-Functional Requirements

  • Performance: Page load time under 2 seconds
  • Security: SQL injection prevention, input validation
  • Usability: Intuitive UI, responsive design
  • Data Persistence: All data stored in MySQL database
  • Error Handling: Graceful error messages for failed operations

Base URL

Expense Endpoints

1. Get All Expenses

Endpoint: GET /api/expenses

Description: Fetch all expenses

Response:

{
  "success": true,
  "data": [
    {
      "id": 1,
      "expense_name": "Grocery Shopping",
      "amount": 99.00,
      "category": "Groceries",
      "expense_date": "2024-11-01",
      "created_at": "2024-11-01T10:30:00Z"
    }
  ]
}

2. Get Single Expense

Endpoint: GET /api/expenses/:id

Description: Fetch a specific expense by ID

3. Create Expense

Endpoint: POST /api/expenses

Description: Create a new expense

Request Body:

{
  "expense_name": "Lunch at Restaurant",
  "amount": 250.00,
  "category": "Food & Drink",
  "expense_date": "2024-11-05"
}

Validation Rules:

  • expense_name: Required, string, max 255 characters
  • amount: Required, number, positive value
  • category: Required, string
  • expense_date: Required, valid date format

4. Update Expense

Endpoint: PUT /api/expenses/:id

Description: Update an existing expense

Request Body: Same as Create Expense

5. Delete Expense

Endpoint: DELETE /api/expenses/:id

Description: Delete an expense

Response:

{
  "success": true,
  "message": "Expense deleted successfully"
}

🗄️ Database Schema

MySQL Database: expense_tracker

Table 1: expenses

Column Type Constraints Description
id INT PRIMARY KEY, AUTO_INCREMENT Unique expense ID
expense_name VARCHAR(255) NOT NULL Name of the expense
amount DECIMAL(10,2) NOT NULL Expense amount
category VARCHAR(100) NOT NULL Expense category
expense_date DATE NOT NULL Date of expense
created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP Record creation time
updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP Record update time

SQL Script:

CREATE TABLE expenses (
  id INT PRIMARY KEY AUTO_INCREMENT,
  expense_name VARCHAR(255) NOT NULL,
  amount DECIMAL(10,2) NOT NULL,
  category VARCHAR(100) NOT NULL,
  expense_date DATE NOT NULL,
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP
);

Table 2: budget

Column Type Constraints Description
id INT PRIMARY KEY, AUTO_INCREMENT Budget ID

created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP Record creation time
updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP Record update time

✅ Development Best Practices

Code Quality

  • Use meaningful variable and function names
  • Add comments for complex logic
  • Keep functions small and focused (single responsibility)
  • Use async/await for asynchronous operations
  • Implement proper error handling with try-catch blocks

Git Workflow

  • Commit frequently with descriptive messages
  • Use branches for new features (feature/expense-crud)
  • Write clear commit messages: "Add expense delete functionality"
  • Push code regularly to backup progress

Security Best Practices

  • Never commit .env files to Git
  • Validate all user inputs on backend
  • Use parameterized queries to prevent SQL injection
  • Sanitize data before displaying in UI
  • Enable CORS only for trusted origins in production

Performance Optimization

  • Use database indexing on frequently queried columns
  • Implement pagination for large datasets (future enhancement)
  • Minimize API calls by caching data when appropriate
  • Optimize images and assets
  • Use React.memo() for expensive components

🔧 Common Issues & Solutions

Backend Issues

Problem: "Cannot connect to MySQL database"

Solution:

  • Check if MySQL service is running
  • Verify .env credentials are correct
  • Ensure database 'expense_tracker' exists
  • Check if firewall is blocking MySQL port (3306)

Problem: "CORS error when calling API"

Solution:

// In server.js, add CORS middleware
const cors = require('cors');
app.use(cors({
  origin: 'http://localhost:3000'
}));

Problem: "Port 5000 already in use"

Solution:

  • Change PORT in .env file to 5001 or another available port
  • Or kill the process using port 5000

Frontend Issues

Problem: "API calls returning 404"

Solution:

  • Verify backend server is running
  • Check API URL in axios calls matches backend port
  • Ensure routes are properly defined in backend

Problem: "Charts not displaying data"

Solution:

  • Check if expense data is being fetched correctly
  • Verify chart data format matches library requirements
  • Console.log the data before passing to chart component
  • Ensure chart library is properly imported

Problem: "Modal not closing after form submission"

Solution:

  • Call the close modal function in the success callback
  • Reset form state after successful submission
  • Check if form submission is actually successful
